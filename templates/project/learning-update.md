# Canonical learning update

[Templates](README.md)

## Problem and evidence

What repeated mistake or new discovery motivates the change? Identify evidence
and distinguish current observation from historical evidence.

## the foundation rule change

Name the canonical skill/procedure/template/tool. State old versus new guidance,
why it generalizes, applicability, exclusions and any conflict resolved.

## Example and acceptance

Provide a standalone example, failure case and checks. Link only the foundation-owned required
resources. Use generic examples without repository lineage maps; preserve any required
third-party notices for actual reused material separately.

## Adoption impact

Which consumers must adapt? Record compatible clarification versus changed policy,
local override handling and any superseded rule. Record the foundation commit/version when
available; do not invent a revision for uncommitted work.

## Validation and remaining limits

Skill/frontmatter, local links, portability and behavior checks as applicable.
Separate documentation review from native/provider/hosted execution.
